# Typst layouts are uploaded in the app and get raw data

Each document type has a built-in layout; further layouts are uploaded in the app, stored in the database with their fonts, chosen per document type and overridable per customer. A layout receives typed data (decimal amounts, ISO dates) and a bundled Typst library for formatting, rather than pre-formatted strings as in Haben, so a corporate design is not limited to rearranging finished text. Rendering runs in-process with no network: Typst packages are only used after the owner approves them by name and version, then cached and pinned with the layout. Before a layout is saved it is rendered with sample data and checked for the mandatory invoice details of § 14 Abs. 4 UStG; the e-invoice XML is generated by the app and attached after rendering, so no layout can break it. An issued document keeps its PDF; changing a layout never alters it.
